# IDE 기본 탐지 경로

`gz ide scan`, `gz ide status`, `gz ide open`의 기본 탐지기는 같은 실제 탐지 구현을 사용한다. 기존에는 각 하위 패키지의 기본 생성자가 고정된 IDE 목록이나 임의의 갱신 시각을 반환해, 부모 패키지에 있던 실제 탐지기와 연결되지 않았다.

## 소유권과 호환성

실제 탐지기와 외부 명령의 타임아웃·프로세스 정리는 `internal/idecore`가 소유한다. `cmd/ide`는 기존 공개 타입과 `NewIDEDetector` 생성자 진입점을 유지한다. 하위 패키지는 실제 탐지 결과를 기존 공개 DTO로 변환한다. 기존 탐지 순서와 IDE 실행 방식은 유지한다.

홈 디렉터리를 조회할 수 없으면 Toolbox와 AppImage의 사용자별 경로 후보를 생략한다. 빈 HOME을 현재 작업 디렉터리에 대한 상대 경로로 해석해 탐색하지 않는다. AppImage의 기존 `/opt` 후보는 유지한다. 기존 nil context 호환 동작은 명시적 정규화로 유지하며, 전달된 context의 취소와 명령별 타임아웃은 바꾸지 않는다.

`status`의 설치 경로·방식·갱신 시각은 탐지 결과에서 가져온다. 하위 DTO의 `ProductCode` 필드는 호환성을 위해 유지하지만 공통 탐지 결과에 없는 값을 만들어 넣지 않는다. 취소 context와 캐시 사용 여부는 탐지기에 전달한다. 실제 설치나 유효 캐시에 IDE가 없으면 고정 예제 목록을 대신 반환하지 않는다.

## 검증

기본 생성자 회귀는 임시 HOME의 실제 캐시 JSON을 읽어 이름·버전·경로·별칭과 설치 정보를 확인한다. 캐시 갱신 시각을 임의로 생성하거나 원본 캐시를 덮어쓰지 않는지, 취소와 빈 캐시를 처리하는지도 확인한다. 이 테스트는 사용자 설정이나 설치된 IDE를 탐색하지 않으며 IDE 프로세스를 실행하지 않는다.

탐지기 내부의 기존 회귀와 프로세스 타임아웃 검사는 구현 소유 패키지로 옮겨 유지한다. 이 검증을 모든 운영체제에서 실제 IDE를 실행한 결과나 출시 성능 조건 충족으로 해석하지 않는다.
