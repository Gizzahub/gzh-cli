# PR/MR 동기화 옵션

`gz git repo sync --include-prs`의 PR/MR 동기화는 지원되지 않는다. 기존 필드와 플래그는 유지하지만, 이 값을 켜면 다른 옵션과의 조합이나 dry-run 여부에 관계없이 명시적인 오류를 반환한다. `--include-prs`의 기본값은 계속 false다.

기존에는 옵션 검증이 이 값을 동기화 기능으로 인정하면서 실제 작업에는 포함하지 않아 요청한 PR/MR을 처리하지 않고 지나갈 수 있었다. Issue 동기화도 GitHub 응답의 PR 항목을 제외하므로 이를 PR 동기화로 해석할 수 없다.

지원되지 않는 요청은 CLI 검증과 직접 엔진 `Sync` 진입점에서 동기화 provider 조회·Git 작업 전에 거부한다. 기본 false의 기존 코드 동기화 경로와 다른 옵션의 검증·기본값 처리 방식은 유지한다. 이 수리는 PR/MR 생성·브랜치 매핑 기능을 추가하지 않는다.

회귀는 PR 단독·코드 조합·dry-run에서 provider와 Git 호출이 없는지, 직접 엔진 호출도 같은 조건으로 거부하는지 확인한다. 기본 false의 provider 조회·코드 작업 경로도 보존한다. CLI 회귀는 독립 `newRepoSyncCmd`의 실제 Cobra 실행 범위이며 루트 초기화나 조상 hook까지 검증한 결과가 아니다. 실제 원격 저장소나 사용자 Git 설치를 실행하지 않는다.
