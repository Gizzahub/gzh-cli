# Clone 세션 재개

`gz git repo clone --resume <세션 ID>`는 저장된 provider·organization과 완료 상태를 복원한다. 새 작업은 `--provider`와 `--org`가 필요하며, 재개할 때는 이 두 플래그를 함께 지정할 수 없다. 이 경로는 `clone-or-update` 명령과 별개다.

## 확인된 원인과 수정

기존 재개 handler는 `Resume` 값을 유지한 채 같은 dispatcher를 다시 호출해 실행기에 도달하지 못했다. 또한 필수 provider/org 플래그가 resume과 상호 배타적으로 선언돼 문서의 재개 호출을 거부했다. 재개 handler가 기존 실행 경로를 직접 호출하고, 새 작업과 재개 중 하나에 필요한 플래그를 검사하도록 수정한다.

세션 JSON을 읽는 두 경로에서 `Session.Options`와 현재 실행 옵션을 같은 포인터로 공유하면 저장된 값이 CLI override를 덮어쓴다. 복원용 옵션과 실행 옵션을 분리해야 한다. 완료 상태와 같은 세션 ID는 유지하며, 완료된 저장소를 다시 clone하지 않는다. 손상되거나 옵션이 없는 세션은 오류로 반환한다.

## 검증 범위

회귀 테스트는 임시 설정 디렉터리, fake provider와 recording Git runner를 사용한다. 실제 Cobra flag 검사, 동일 세션 유지, 완료 항목 제외, 복원 이후 실행 옵션과 잘못된 세션의 오류를 확인한다. 무한 재귀 회귀는 제한 시간이 있는 자식 테스트 프로세스로 격리한다. 실제 Git 호스팅 서비스나 사용자 설정은 검증 대상으로 사용하지 않는다.

이 수정은 새 공개 Go API나 릴리스 성능·커버리지 기준을 정의하지 않는다. 전체 출시 판정에는 별도의 기존 출시 게이트가 필요하다.
